# 0.5.1: FLUID 0.7.6 at the Seam

*2026-11-12 · additive · every 0.3.0 to 0.5.0 document stays valid*

0.5.1 widens the FLUID seam by one release and adds a second worked example.
It is on PyPI as `flux-spec` 0.5.1.

## FLUID 0.7.6

FLUID 0.7.6 is vendored verbatim in `vendor/fluid/fluid-schema-0.7.6.json`, and
a weekly workflow compares it with the schema FLUID publishes. A `.fluid.yml`
that declares `fluidVersion: "0.7.6"` is validated against it, and
`Simulation.emits[].fluidVersion` accepts the exact pin `"0.7.6"`:

```json
"enum": ["0.7.3", "0.7.4", "0.7.5", "0.7.6"]
```

A range such as `^0.7.3` reaches 0.7.6 as well, now that it is vendored, under
the same rules as before: the contract's own `fluidVersion` must satisfy the
range, and so must at least one vendored schema.

## A second example

[`examples/towers-tenant-renewal/`](https://github.com/Agenticstiger/flux/tree/main/examples/towers-tenant-renewal)
follows a tower company's tenants as SLA breaches rise, and emits renewal-risk
rows for a FLUID 0.7.6 contract. CI validates it with the rest of the examples.

## Upgrading

Nothing that validated under 0.5.0 is refused. `flux-schema-0.5.0.json` is
immutable and still refuses an exact `"0.7.6"` pin, so a tool or editor that
validates against that file refuses it: use `flux-schema-0.5.1.json` or later,
or `flux-schema-latest.json`, which `flux_spec.validate` reads. The enforcement
contract and the bundle manifest are unchanged from 0.5.0.

Full field-by-field diff: [Changelog](/flux/schema/changelog).
