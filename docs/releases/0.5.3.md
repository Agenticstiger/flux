# 0.5.3: The FLUID 0.7.7 Preview Moves

*2026-11-18 · every FLUX document stays valid · the 0.7.7 preview is re-pinned*

0.5.3 moves the FLUID 0.7.7 preview to a newer forge-cli commit. The FLUX
schema only widens its compatibility window, so every FLUX document that
validated under 0.5.2 still does. A contract that declares FLUID 0.7.7 is
checked against the new pin, which accepts three new things and refuses three
malformed enum lists.

## What a 0.7.7 contract may now carry

- An enum level written as quoted text, with any character but a control
  character and its own quote doubled:
  `enum('Dr.', '>10000', 'O''Brien', 'a, b')`. Before, a dot or a `>` in a
  level was refused.
- `protobuf.field` on a column: its field number in the `.proto` that
  forge-cli generates for a Protobuf topic, from 1 to 536870911, outside
  19000 to 19999.
- `rules: true` on a Confluent schema registry block, which registers the
  expose's error-severity row checks as Confluent data-contract rules. A Glue
  registry block is refused it.

## What it refuses now

These column types validated under 0.5.2:

| Type | Write instead |
|---|---|
| `enum('a' 'b')`, levels without commas | `enum('a', 'b')` |
| `enum(a,,b)`, an empty level | `enum(a, b)` |
| a quoted level that holds a tab or a newline | the level without it |

## Upgrading

Validate your bundles with 0.5.3 before you rely on it: each refused type is
named with its path in the contract. `verify` checks a pack's 0.7.7 contracts
against the preview the running release carries, so a pack that 0.5.2 made
from such a contract fails under 0.5.3 with `bundle no longer validates`.
Verify that pack with flux-spec 0.5.2, or fix the contract, pack it again and
sign the new manifest. Contracts on the FLUID releases 0.7.3 to 0.7.6, the
enforcement contract and the bundle manifest are unchanged.
