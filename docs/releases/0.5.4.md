# 0.5.4: Input Bounds

*2026-11-19 · the window widens · no schema constraint changes*

0.5.4 widens the compatibility window and changes no constraint of the schema.
The validator, `pack`, `verify` and the reference enforcement gate now refuse
input that is outside the JSON data model or past a limit an implementation may
set, and they report a hostile bundle where 0.5.3 raised an exception. A
document inside the bounds validates as it did.

## What is refused now

A bundle with one of these validated under 0.5.3. Each refusal names its file,
line and column.

| Input | Write instead |
|---|---|
| `credibility: .nan`, a NaN weight, level or lifecycle mix; `.inf`, or a float past what a double holds, where the schema does not bound the field | a finite number |
| a float that needs more than 1,000 digits written out, such as `1.0e-1001` or `0.e-10000000` | a number of at most 1,000 digits |
| an integer of more than 4,300 digits | a shorter one |
| a YAML document that writes out more than 1,000,000 values or 64 MiB of characters once its aliases and merge keys are written out, nests deeper than 64 levels, holds itself through an alias, or names more than 1,000,000 mappings in its merge keys | a document that does not expand so far |
| a bundle file that is not UTF-8 text, on a host whose locale is not UTF-8 | the file saved as UTF-8 |

A NaN was worse than a refusal: it is neither above nor below anything, so a
`credibility: .nan` satisfied a Simulation's `minCredibility`. Every numeric
gate of the validator now fails a NaN as well, in case a document is put
together by code.

## The enforcement gate

`decide` answers `INVALID_POLICY`, with the cause in words, where 0.5.3 raised
or read the input as another one:

- a policy that RFC 8785 cannot write: a number that is not finite, an integer
  past 2^53-1, bytes, a key that is not a string, nesting too deep. Its
  decision names the digest of `{}`, as for a policy that is not an object;
- a skill whose `tokenBudget` is present and not an integer, which 0.5.3
  allowed as a skill that narrowed nothing;
- a skill that is not an object: `[]`, `false`, `0` and `""` read as no skill
  in 0.5.3. `{}` is still a skill that names no budget.

A request is decided as before. The conformance vectors gain three, 37 in all.

## What is reported now instead of raised

A scalar PyYAML cannot build (`!!int abc`, an integer of more than 4,300
digits), a document nested thousands of levels deep, a value RFC 8785 cannot
write in a locked Module, a broken gzip stream, a NUL byte in an archive path,
and a manifest that is not UTF-8 or is nested too deeply are now reported with
their position, by `validate`, `pack` and `verify`.

## Upgrading

Validate your bundles with 0.5.4 before you rely on it. A pack that 0.5.3 made
from a bundle with one of the inputs above verifies with 0.5.3 and fails under
0.5.4 with `bundle no longer validates`: verify it with flux-spec 0.5.3. To get
a pack that 0.5.4 verifies, fix the document and make a new pack, which needs a
new signature. The FLUID releases and the 0.7.7 preview pin, the enforcement
contract and the bundle manifest are unchanged. VERSIONING.md says why none of
this resets the window (Input bounds).
