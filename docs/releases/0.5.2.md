# 0.5.2: Keys at the Seam, and Packs That Outlive a Release

*2026-11-17 · additive · every 0.3.0 to 0.5.1 document stays valid*

0.5.2 lets a Simulation emit for a FLUID 0.7.7 contract, which declares its
keys, and makes `verify` accept evidence packs made by earlier releases. It is
on PyPI as `flux-spec` 0.5.2.

## The FLUID 0.7.7 preview

FLUID 0.7.7 is not released yet. It carries expose relationships (composite
keys included) and validity windows, which the engine reads keys and history
from. 0.5.2 vendors it as a preview in
`vendor/fluid-preview/fluid-schema-0.7.7.json`, verbatim, pinned to a
forge-cli commit and the sha256 of its bytes (`vendor/fluid-preview/pins.json`).
CI re-creates the file from the pin and fails on any byte difference.

Only an exact pin selects the preview:

```json
"enum": ["0.7.3", "0.7.4", "0.7.5", "0.7.6", "0.7.7"]
```

A range never reaches a preview, so `^0.7.3` still stops at 0.7.6, and the
validator refuses an emit whose range would select a 0.7.7 contract, with a
message that says to pin `"0.7.7"` exactly. The preview can change: its pin
moves only in a flux-spec release, with a note in that release's schema diff.
When FLUID releases 0.7.7, the release copy replaces the preview, an exact pin
keeps working, and ranges start to reach it.

## Packs from earlier releases verify

`verify` re-validates a pack against the schema its manifest's `schemaId`
names, when that schema is inside the compatibility window. Before 0.5.2 it
refused every schema but the current one, so each release broke the packs
made by the one before, every `fluxsim ship` archive included. A pack made
with flux-spec 0.5.0 or 0.5.1 now verifies without a re-pack, which would break
a detached signature over the manifest.

`pack` now refuses a bundle that holds a symbolic link before it reads
anything. It used to read through a linked file, so the target's bytes went
into the archive.

## Upgrading

Nothing that validated under 0.5.1 is refused. `flux-schema-0.5.1.json` is
immutable and still refuses an exact `"0.7.7"` pin, so a tool or editor that
validates against that file refuses it: use `flux-schema-0.5.2.json` or
`flux-schema-latest.json`, which `flux_spec.validate` reads. The enforcement
contract and the bundle manifest are unchanged from 0.5.0.
